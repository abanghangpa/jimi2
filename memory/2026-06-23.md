## Session: Scanner Report Cron Fix

### Problem
Jimi Scanner Report cron was failing with "Context overflow: prompt too large for the model" — the default `openrouter/free` model was routing to models with small context windows that couldn't handle the ~60KB scanner JSON output.

### Solution Applied
1. Created `jimi_audit/scripts/scanner_brief.py` — extracts only report-relevant fields from scanner output (5KB vs 60KB). Backup option.
2. Set `lightContext: true` on the cron job — reduces workspace context loading
3. Restored original full scanner message — brief script exists as fallback
4. Model set back to `openrouter/free` (default) — relies on agent's 60+ model fallback chain for automatic retry if context overflow occurs

### Key Insight
- The agent config has a massive fallback chain (60+ models including gpt-5.5-pro with 200K context)
- When a model fails, the gateway tries the next fallback automatically
- `lightContext: true` reduces overhead without losing report quality
- If context overflow persists, switch cron to use `scanner_brief.py` instead

- `jimi_audit/scripts/scanner_brief.py` (NEW) — compact scanner output wrapper
